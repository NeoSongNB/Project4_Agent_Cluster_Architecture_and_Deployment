# K8s 核心概念速查表

> 一页纸速查。忘了某个概念是干嘛的，回这里瞄一眼。

## 一句话核心概念

| 概念 | 一句话作用 | 生活类比 |
|------|-----------|---------|
| **Cluster（集群）** | 一整套 K8s = 大脑 + 一群机器 | 整个集装箱码头 |
| **Control Plane（控制平面 / 大脑）** | 做决策、下命令，不亲自跑容器 | 码头调度指挥室 |
| **Node（节点）** | 真正跑容器的机器 | 码头的泊位 + 起重机 |
| **Pod** | 最小运行单位，装着容器，用完即弃 | 装货物的标准托盘 |
| **Deployment** | 保证"永远有 N 个健康 Pod 在跑"，管扩缩容和更新 | 牧场存栏管理员 |
| **Service** | 给一组 Pod 固定入口 + 负载均衡 | 餐厅前台总机 |
| **Ingress** | 把外部流量按域名/路径引进来 | 写字楼大堂前台 |
| **ConfigMap** | 存普通配置，与镜像解耦 | 参数说明卡 |
| **Secret** | 存敏感信息（密码/密钥） | 保险柜里的密码条 |

## 一句话核心思想

> **声明式**：你只描述"想要的最终状态"，K8s 通过不停"对比现实与期望、自动纠偏"（调谐循环）来一直帮你维持它。

## K8s 帮你自动做的 5 件事

| 能力 | 说明 |
|------|------|
| **自愈** | 容器挂了自动拉起新的 |
| **调度** | 自动把容器安排到合适的机器 |
| **弹性伸缩** | 按负载自动扩容/缩容 |
| **滚动更新 / 回滚** | 平滑换新版，出问题一键回退 |
| **服务发现 / 负载均衡** | 服务互相找得到、流量自动均分 |

## Docker vs K8s

| | Docker | K8s |
|---|--------|-----|
| 管什么 | 单个容器 | 成百上千容器 + 多台机器 |
| 角色 | 造集装箱、跑单个箱子 | 指挥整支船队的舵手 |
| 关系 | 打工人 | 站在 Docker 之上的包工头 |

## 常用 kubectl 命令（看个眼熟即可）

```bash
kubectl get nodes            # 看集群里有哪些机器
kubectl get pods             # 看 Pod 运行状态
kubectl get svc              # 看 Service
kubectl apply -f xxx.yaml    # 部署 / 更新（声明式核心命令）
kubectl logs <pod名>         # 看某个 Pod 的日志
kubectl rollout undo ...     # 回滚到上一个版本
kubectl delete -f xxx.yaml   # 删除某个资源
```

## 该不该用 K8s（快速判断）

- 一两个服务、流量不大 → **不用**，`docker run` / `compose` / Serverless 容器即可
- 几个服务、想省心 → 优先**云容器服务 / Serverless 容器**
- 服务多、跨多机、要精细伸缩灰度 → **可考虑托管 K8s**
- 团队没人懂 K8s → **先别碰**
- AI 团队务实路线 → **业务打镜像跑 + 数据买云托管**
