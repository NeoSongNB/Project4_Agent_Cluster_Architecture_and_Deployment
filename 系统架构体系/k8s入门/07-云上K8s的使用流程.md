# 07 - 云上 K8s 的大致使用流程

这一章走一遍"从零到把应用跑在云上 K8s"的**整体流程**，让你对使用体验有个画面感。

> 说明：这**不是一步步的实操教程**（各家云控制台不一样、也会变）。目的是让你知道"整件事大概分几步、每步在干嘛"，建立心智地图。真要操作时，照着你所选云厂商的官方文档走即可。

## 全流程一图看懂

```
第 0 步  把应用打成 Docker 镜像，推到镜像仓库
              ↓
第 1 步  在云控制台创建一个 K8s 集群
              ↓
第 2 步  拿到 kubeconfig，让本机的 kubectl 能连上集群
              ↓
第 3 步  写好 YAML（Deployment / Service / Ingress）
              ↓
第 4 步  kubectl apply 部署上去
              ↓
第 5 步  配置对外访问（Service / Ingress + 域名 + HTTPS）
              ↓
第 6 步  日常运维：查看、扩缩、更新、看监控
```

下面逐步说明。

## 第 0 步：准备镜像（Docker 那套）

K8s 跑的还是容器，所以第一步和 Docker 教程一样：

- 用 `Dockerfile` 把你的 AI 服务打成镜像
- 推送到一个**镜像仓库**（云厂商都有自己的镜像仓库服务，如阿里云 ACR；也可用 Docker Hub）
- 这样集群里的机器才能拉取到你的镜像

## 第 1 步：创建集群（点几下控制台）

登录云厂商控制台，进入容器服务（ACK / TKE / EKS…），点"创建集群"：

- 选地域、选 K8s 版本
- 选要几台 Node、什么规格（或者选 Serverless / 弹性模式，让它自动伸缩）
- 点确定，等几分钟——**一套集群就好了**

> 这一步就是第 06 章说的"拎包入住"：控制平面（大脑）云厂商已经帮你建好并托管了，你只是选了几间房。

## 第 2 步：连上集群（配置 kubectl）

你在自己电脑上通过 `kubectl` 这个命令行工具来操作集群。要让它连上刚建的集群，需要一份"通行证"叫 **kubeconfig**：

- 在控制台把集群的 kubeconfig 复制/下载到本机
- 之后 `kubectl` 就知道"我要操作的是哪个集群、凭什么身份"

验证一下连通：

```bash
kubectl get nodes      # 能列出集群里的机器，就说明连上了
```

## 第 3 步：写 YAML（描述你的期望状态）

回到第 05 章的声明式思想：把你想要的东西写成 YAML。典型的一个 AI 服务需要：

- 一个 **Deployment**：用哪个镜像、跑几个副本
- 一个 **Service**：给这些 Pod 一个稳定入口
- 一个 **Ingress**：把域名流量引进来（如果要对外）
- 可能还有 **ConfigMap / Secret**：配置和密钥

（这几个概念忘了就回 [第 04 章](04-必须认识的几个核心概念.md) 复习。）

## 第 4 步：部署（一条命令）

把写好的 YAML 交给集群：

```bash
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml
kubectl apply -f ingress.yaml
```

K8s 收到后，自动在合适的 Node 上把 Pod 跑起来。看看效果：

```bash
kubectl get pods       # 看 Pod 是否都在 Running
kubectl get svc        # 看 Service 入口
```

## 第 5 步：对外暴露（域名 + HTTPS）

让外部用户能访问：

- 通过 Service（LoadBalancer 类型）或 Ingress，云厂商会给你分配一个公网入口
- 把你的域名解析到这个入口
- 配上 HTTPS 证书（云厂商一般能一键签发/托管）

搞定后，用户访问 `api.你的域名.com` 就能用上你的 AI 服务了。

## 第 6 步：日常运维（都靠声明式 + 几条命令）

上线后的日常操作，基本就这几类：

| 你想做的事 | 怎么做 |
|-----------|--------|
| 看现在跑得怎么样 | `kubectl get pods` / 看云控制台的可视化面板 |
| 扩容到 10 个副本 | 把 YAML 里 `replicas` 改成 10，再 `kubectl apply` |
| 发新版本 | 把镜像版本改成 v2，再 `kubectl apply`（自动滚动更新） |
| 出问题回滚 | `kubectl rollout undo`（一键回到上个版本） |
| 看日志排查 | `kubectl logs <pod名>` |
| 看监控告警 | 云控制台自带的监控大盘 |

> 注意：大多数**改动**都遵循同一个套路——**改 YAML → apply**，剩下的交给 K8s 自动调谐。这就是第 05 章声明式思想的实际体感。

## 你会发现：云控制台把很多事可视化了

值得强调：用托管 K8s 时，上面很多操作**在云控制台点点鼠标也能完成**，还带图形化的监控、日志、伸缩配置界面。你不一定非得敲 `kubectl`。

> 对入门和中小团队来说，很多时候**控制台点一点 + 少量 YAML** 就够用了，不必一上来就追求全命令行/全自动化。

## 小结

- 云上用 K8s 的整体流程：**打镜像 → 建集群 → 连集群 → 写 YAML → apply 部署 → 配对外访问 → 日常运维**。
- 建集群、连集群主要在控制台点几下 + 配一份 kubeconfig。
- 部署和改动的核心套路始终是：**改 YAML → `kubectl apply`**，声明式自动生效。
- 托管 K8s 的控制台把监控、日志、扩缩容都可视化了，不必全靠命令行。

流程你有画面了。最后一章，我们回到最该冷静思考的问题：**你现在这个项目，到底该不该上 K8s？**
