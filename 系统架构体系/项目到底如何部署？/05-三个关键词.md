# 05 - 三个关键词：静态托管、Serverless、云服务

全景图里反复出现三个词：**静态托管、Serverless、云服务**。它们是现代部署的三大支柱。这一章一次性把"是什么、解决什么"讲清楚，后面各部分就是它们的展开。

## 关键词一：静态托管（前端往哪放）

**静态文件**：内容固定、不需要服务器实时计算就能直接给用户的文件——比如 HTML、CSS、JS、图片。前端 `build` 出来的产物，本质就是这么一堆静态文件。

**静态托管**：把这些文件放到一个专门"存文件 + 对外提供访问"的服务上，用户来了直接下载即可。

> 类比：前端产物就像一叠印好的宣传单，你不需要一个"厨师"现做，只要找个**货架**摆出来，谁来了自取。静态托管就是这个货架。

在现代方案里，这个"货架"就是 **OSS（对象存储）+ CDN**。这也是为什么前端部署特别简单——它不需要"运行"，只需要"被存起来供人下载"。

## 关键词二：Serverless（后端在哪跑）

**Serverless（无服务器）**：你把代码/镜像交给平台，平台负责运行它、按请求自动伸缩、按用量收费。你**看不到也不用管**底下是哪台服务器。

它和传统方式的核心区别：

| | 传统服务器 | Serverless |
|---|-----------|-----------|
| 谁管服务器 | 你 | 云平台 |
| 计费 | 包月，空转也花钱 | 按请求量/用量，没请求几乎不花钱 |
| 扩容 | 手动买、手动配 | 自动伸缩 |
| 保活 | 自己守护进程 | 平台负责拉起、重启 |

> 类比：传统方式像**自己买车**（要养车、保养、停车位都得操心）；Serverless 像**打网约车**（要用就来，用完就走，按次付费，车的维护不用你管）。

后端需要"运行代码、处理请求、算逻辑"，所以它得放在能"跑起来"的地方——这就是 Serverless 的活。（后端为什么还要先打成 Docker，第四部分细讲）

## 关键词三：云服务（能力直接买现成的）

**云服务**：那些通用的、你自己搭很麻烦的能力，云厂商已经做成了现成的服务，你直接开通、调用即可。典型的两类：

- **云数据库**：不用自己装 PostgreSQL/MySQL，云厂商给你一个托管好的数据库，自动备份、扩容、高可用。
- **AI 云 API**：不用自己部署大模型（那要昂贵的 GPU），直接调用通义、豆包等提供的 API，按调用量付费。

> 类比：你想喝牛奶，不用自己养一头牛（自建），直接去超市买一盒（云服务）。

## 三者怎么配合

把三个关键词放回全景图就一目了然：

- **静态托管**解决"前端放哪" → OSS + CDN
- **Serverless** 解决"后端在哪跑" → 跑你的 Docker 镜像
- **云服务**解决"数据存哪、AI 从哪来" → 云数据库 + AI 云 API

而 **CI/CD** 则是把它们自动串起来的引擎。

> [配图：三个关键词做成三根柱子，共同撑起"现代部署"这个屋顶，CI/CD 作为地基]

## 小结

| 关键词 | 解决什么 | 现代方案 | 类比 |
|--------|---------|---------|------|
| 静态托管 | 前端放哪 | OSS + CDN | 货架摆宣传单 |
| Serverless | 后端在哪跑 | 跑 Docker 镜像 | 打网约车 |
| 云服务 | 数据/AI 从哪来 | 云数据库 + AI API | 超市买牛奶 |

三个支柱认识了，理念篇就结束了。接下来进入第二部分：把这一切**自动串起来的引擎——CI/CD**。
