# 02 - 传统部署的痛点与缺陷

上一章我们走完了"自己一台服务器"的完整部署流程。能用，但用起来处处是坑。这一章把痛点一个个摆出来——记住这些痛点，因为**现代部署的每一个好处，都是在解决这里的某个痛点**。

## 痛点一：环境全靠手动装，极易翻车

服务器是"裸"的，Python、Node、数据库、Nginx 都要自己装。

- 版本装错一个，整条链路跑不起来
- 本地能跑、服务器跑不起来，排查半天
- 换一台新服务器，所有环境要**从头再装一遍**

> 这就是经典的"在我电脑上是好的呀"，只不过战场换到了服务器上。

## 痛点二：每次更新都要手动重来

改一行代码想上线，你得：登录服务器 → 拉代码 → 装依赖 → 重启服务 → 刷新 Nginx……

- 步骤多，**漏一步就出问题**
- 纯手工操作，**半夜发版发到崩溃**
- 出了问题想回滚到上个版本，还得手动折腾

## 痛点三：服务要自己"守护"，容易挂

后端进程一关终端就停，得靠 `pm2` / `systemd` 守着。可是：

- 服务器**宕机、重启，服务就没了**
- 进程内存泄漏、被打挂，可能半夜没人管
- 你得自己配监控、配告警，否则挂了都不知道

## 痛点四：扛不住流量，扩容很难

平时没人访问，服务器闲着；突然来一波流量（比如上了热搜），单台服务器扛不住，直接崩。

- 想扩容？得**再买服务器、再装一遍环境、再配负载均衡**，来不及
- 流量过去了，多买的服务器又闲置浪费钱
- **一台服务器 = 一个单点**，它一挂，整个网站全挂

## 痛点五：花钱买的是"一直开着"，不是"用了多少"

传统服务器是**包月/包年**的：

- 哪怕半夜没有一个人访问，它也在**烧钱空转**
- 为了应对高峰，你还得按最高峰去买配置，**平时大量浪费**

## 痛点六：安全和运维是个无底洞

服务器一旦暴露在公网，你就要操心：

- 系统漏洞要打补丁、防火墙要配、被黑客扫描攻击要防
- 数据库要自己备份，磁盘满了要自己清，证书过期要自己续
- 这些都是**跟业务毫无关系、但又不得不做**的杂活

## 一句话总结传统方式的本质缺陷

> **你买的是一台"机器"，但你真正想要的是"我的应用能稳定地跑起来"。中间那一大堆装环境、守进程、扩容、运维、安全的活，全被强行塞给了你。**

你本来只想写代码、发布应用，结果一半精力花在了和业务无关的服务器运维上。

> [配图：一个开发者被"装环境、守进程、扩容、打补丁、备份、续证书"等一堆杂事包围，头顶冒烟，而"写代码"只占很小一块]

## 小结

传统部署的六大痛点：

| 痛点 | 具体表现 |
|------|---------|
| 环境手动装 | 版本易错、换机重装、容易翻车 |
| 更新手动做 | 步骤多、易漏、难回滚 |
| 服务要守护 | 宕机就没、要自己配监控 |
| 扩容难 | 扛不住流量、扩容慢、单点故障 |
| 计费不划算 | 空转也烧钱、按峰值买浪费 |
| 运维无底洞 | 打补丁、备份、续证书等杂活 |

这些痛点归根结底是一句话：**你被迫管了太多本不该你管的东西**。

那有没有办法，让你**只管写代码和发布，其余全交给别人**？有——这就是下一章要讲的现代部署。
