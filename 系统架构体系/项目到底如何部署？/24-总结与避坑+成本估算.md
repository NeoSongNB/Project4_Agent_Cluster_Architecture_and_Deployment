# 24 - 总结与避坑 + 成本估算

恭喜你走到最后一章。这里我们把整套体系收个尾：串一遍全貌、盘点最容易踩的坑、算一笔真实的钱，并聊聊这套方案的适用边界。

## 一张表回顾整套体系

| 部分 | 传统做法 | 现代做法（本教程） |
|------|---------|-------------------|
| 前端 | 自己 Nginx 托管 | build → **OSS + CDN** |
| 后端 | 服务器起进程 + 守护 | Docker 镜像 → **Serverless** |
| 数据库 | 自己装、自己备份 | **云托管数据库** |
| AI | 自己部署大模型 | **云端 AI API** |
| 更新上线 | 手动登录、拉代码、重启 | **CI/CD**，push 即部署 |
| 域名/HTTPS | 手动配、手动续证书 | CNAME + **一键 HTTPS 自动续期** |
| 运维 | 全是你的 | **交给云厂商** |

核心一句话：**你只管写代码和 push，其余交给托管服务。** 支撑这一切成立的地基是**无状态思维**（第 18 章）。

## 常见避坑清单

上线路上最高频的坑，照着躲：

### 备案坑
- **域名没备案，国内访问被拦**。备案要几天到几周，**一开始就去办**，别等最后卡住。

### CORS 跨域坑
- 前端调后端报跨域错误 → 是后端没配 CORS。后端 `allow_origins` 填**你的确切前端域名**，生产别用 `"*"`（第 21 章）。

### CDN 缓存坑
- 更新了前端但线上还是旧的 → 是 **CDN 缓存**没刷新。部署后记得刷新缓存；HTML 入口文件可设短缓存、带 hash 的资源可长缓存。

### 端口不对坑
- 后端部署上去起不来 → 多半是**监听端口和平台要求不一致**。看平台文档，对齐端口（第 15 章）。

### 密钥泄露坑
- 把数据库密码、AI 密钥**写进代码提交上去** → 极其危险。一律走**环境变量 / Secrets**（第 16、17 章）。

### 冷启动误判坑
- 偶尔第一个请求慢，以为是 bug → 其实是 Serverless **冷启动**，正常现象。介意的话开预留实例（第 14 章）。

### 无状态坑
- 把上传文件/会话存在实例本地 → 换个实例就丢。文件进 OSS、会话用 Token/缓存（第 18 章）。

### 长任务坑
- 一个请求里跑几分钟大任务 → 撞上 Serverless 时长限制。改成**异步任务 + 消息队列**（第 14 章）。

## 成本估算：一个月大概花多少

以一个**起步期、流量不大**的 AI 问答应用为例（数字为量级示意，具体以云厂商实时价格为准）：

| 项目 | 计费方式 | 起步期大致花费 |
|------|---------|--------------|
| OSS 存储 | 按存储量 | 几毛 ~ 几块 / 月 |
| CDN 流量 | 按下载流量 | 流量小，几块 ~ 几十块 / 月 |
| Serverless 后端 | 按请求数 × 时长 | **没人访问≈0**，起步几块 ~ 几十块 / 月 |
| 云数据库 | 最小规格包月 或 Serverless 按量 | 几十块 / 月（最便宜规格） |
| **AI API** | 按 token 用量 | **通常是大头**，取决于调用量 |
| 域名 | 按年 | 几十块 / 年 |

> 关键结论：
> - **除了数据库最小规格和域名，其余基本"用多少花多少"**，没人用时几乎不花钱——这对起步项目极友好。
> - **AI API 往往是最大开销**。务必做**用量限制 + 告警**，防止被刷爆（第 17 章）。
> - 对比传统：包一台够用的服务器，哪怕没人访问，一个月也是稳定几十上百块在烧。

## 这套方案的适用边界

**非常适合：**
- 中小项目、创业项目、AI 应用、个人作品
- 流量不稳定、有明显高峰低谷
- 团队小、没有专职运维

**长大后要重新评估：**
- 流量变得**巨大且持续满负载**：Serverless 按量算可能比自建集群贵，届时可考虑 K8s 等方案（见 [K8s 入门](培训班/基础阶段/系统架构体系/k8s入门/README.md)）
- 有**特殊合规/私有化**要求：可能需要自己掌控基础设施

> 但对本教程面向的绝大多数场景，现代托管方案是**最省心、最省钱、上线最快**的选择。等真的长到需要换方案，那已经是"幸福的烦恼"了。
